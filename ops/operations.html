일상 운영 ​

gaea.sh 운영 명령, 웹 운영 콘솔, 외부 AI 에이전트(MCP) 연결 설정, 문제 해결.

1. 일상 운영 ​

기동·정지·재기동·로그는 gaea.sh 래퍼로 합니다. 브라우저로 같은 일을 하는 웹 운영 콘솔도 있으며, 제품 자체의 어드민 콘솔과는 역할이 나뉩니다. 외부 AI 에이전트(MCP) 접속면도 그 어드민 콘솔에서 켭니다.

1-1 gaea.sh — 일상 운영 래퍼 ​

docker compose 를 직접 입력하면 아래 세 가지 실수를 매번 직접 피해야 합니다. 또 1.3.0 번들은 루트에 compose 파일이 없고 모두 system/ 에 있습니다. 아래 표 오른쪽 열의 원시 명령은 번들 루트에서 ./gaea.sh compose … 로 같은 인자를 주어 실행합니다(오버레이·이미지 태그·프로젝트 디렉터리는 래퍼가 맞춥니다).

  • --no-build 누락
  • restart 와 up -d 혼동
  • edge 재기동 누락으로 인한 전면 502

래퍼는 이 세 가지를 자동으로 처리합니다.

주의 ./gaea.sh restart 는 docker compose restart 와 다릅니다. docker compose restart 는 같은 컨테이너를 다시 띄울 뿐이라 바뀐 .env 를 읽지 않습니다. .env 를 고친 뒤에는 반드시 ./gaea.sh restart(컨테이너 재생성 + edge 재기동)를 씁니다.

backup · restore 가 이 래퍼에 있는 이유 ​

두 명령은 compose 오버레이(jdbc·pg·ha)와 이미지 태그가 정확히 지정돼야 올바른 인스턴스를 대상으로 동작합니다. 래퍼가 이 지정을 맡으므로, 백업·복원도 래퍼로 실행합니다. 오버레이를 하나라도 빠뜨리면 다른 인스턴스를 백업할 수 있습니다.

1-2 웹 운영 콘솔 ​

브라우저에서 일상 운영·정지 백업·복원·복구 리허설을 수행합니다.

실행 주체는 여전히 호스트의 gaea.sh·restore-rehearsal.sh 이고, 웹 계층에는 docker 소켓이 없습니다.

1-3 어드민 콘솔과의 역할 분담 ​

참고 제품이 살아 있을 때 온라인 백업의 주 수단은 어드민 콘솔입니다. 웹 운영 콘솔의 정지 백업은 서버를 내려야 하는 백업이며, 업그레이드·이설처럼 정지가 전제인 상황과 제품이 뜨지 않아 어드민 콘솔에 들어갈 수 없는 상황을 위한 것입니다.

어드민 콘솔(제품 자체, /admin)은 운영 콘솔과 다른 화면이지만 운영과 맞닿아 있습니다. 「시스템 관리자」 탭의 카드 가운데 운영과 직접 관련된 것은 아래와 같습니다(MCP 서버 카드는 1-4).

1-4 외부 AI 에이전트(MCP) 연결 설정 ​

제품 서버가 직접 제공하는 외부 AI 에이전트 접속 주소입니다. Claude Code 같은 MCP 클라이언트가 <서버주소>/api/mcp 에 접속해 제품 도구를 호출합니다. 통신 방식은 Streamable HTTP 입니다. POST 는 initialize·JSON-RPC, GET 은 알림 스트림, DELETE 는 세션 종료이며, 세션은 Mcp-Session-Id 헤더로 이어집니다.

참고 기본은 꺼짐입니다. 켜지 않은 서버의 /api/mcp 는 404 mcp_disabled 로만 응답합니다. 별도 프로세스로 띄우는 방식(gaea-mcp stdio · gaea-mcp --http 5181)은 이 설정과 관계없이 그대로 쓸 수 있습니다.

켜는 절차 — 어드민 콘솔

  1. 어드민 콘솔(/admin) 「시스템 관리자」 탭의 「MCP 서버」 카드에서 토글을 켭니다. 설정은 DB 에 저장되고 즉시 반영되므로 API 서버 재기동은 필요 없습니다.
  2. 카드의 복사 버튼으로 엔드포인트 주소(<서버주소>/api/mcp)를 받아 사용자에게 전달합니다. 상태 배지가 켜짐 · 세션 n개 · 마지막 호출 …전 · 도구 192개 로 바뀌면 열린 것입니다.
  3. 사용자는 개인 액세스 토큰(PAT, gpat_…) 을 발급받아 Authorization: Bearer gpat_… 헤더로 붙습니다. 예: claude mcp add --transport http gaea http://<호스트>/api/mcp --header "Authorization: Bearer gpat_…"
  4. 브라우저에서 붙는 클라이언트가 있으면 카드의 허용 오리진에 그 오리진을 적습니다(아래).
  • 인증은 PAT 전용 — 브라우저 로그인 세션 토큰으로는 붙지 못합니다. PAT 는 제품의 「내 정보 → 개인 액세스 토큰」에서 사용자가 직접 발급합니다.
  • 라이선스 — 기능 플래그 agent-mcp(Enterprise 전용). 미보유 배포에서는 토글을 켜도 접속이 거부됩니다.
  • 도구 수는 PAT 권한을 따라갑니다 — 일반 PAT 192개, 읽기 전용 PAT 81개(변이 도구 111종 제외). 주소 뒤 ?profile=read·?profile=help 로 더 좁힐 수만 있고 넓힐 수는 없습니다.
  • 상태 조회 — GET /api/mcp/status 가 enabled·url·transport·profileDefault·sessions·lastCallAt·toolCount·entitled·allowedOrigins 를 돌려줍니다. 설정 자체는 GET/PUT /api/admin/mcp-settings.
  • 감사 — 설정 변경은 UPDATE_MCP_SETTINGS 로 기록됩니다. 도구 실행은 화면 조작과 같은 API 를 거치므로 권한 검사와 감사 기록도 같습니다. 활동 로그에는 surface='mcp' 와 사용한 PAT 이름이 남습니다.

표 1-5 MCP 엔드포인트 상태코드 해독표

주의 이 엔드포인트는 평문 HTTP 로 PAT 를 받습니다. 반드시 TLS 종단 프록시(edge) 뒤에 두고, 사내망 밖으로 여는 경우 TLS 없이 노출하지 마십시오. 토큰이 새면 그 사용자의 권한 전체가 그대로 넘어갑니다.

주의 세션 수·마지막 호출 시각은 프로세스 메모리에 있습니다 — API 서버를 재기동하면 0 으로 돌아갑니다(설정 자체는 DB 라 유지됩니다). 다중 노드 HA 에서는 같은 세션이 같은 노드로 가도록 스티키 라우팅이 필요합니다.

참고 이 기능이 담긴 빌드로 업그레이드한 직후에는 API 서버를 한 번 재기동해야 엔드포인트가 뜹니다. 그 뒤로는 켜고 끄는 데 재기동이 필요 없습니다.

3. 문제 해결 ​

폐쇄망 배포에는 /metrics 지표가 없으므로, 제품 안에서 확인할 수 있는 6가지 상태 정보로 진단합니다. 증상별 조치와 설치기 검사 메시지도 함께 싣습니다.

3-1 의 표면 6종은 모두 로그인하거나 로그를 열어야 보입니다. 다음 세 가지 상황에서는 운영 알림이 메일·인앱 종·지표 게이지로 알립니다. 백업이 계속 실패할 때, 라이선스 만료가 가까울 때, 업그레이드 뒤 마이그레이션 실패로 서버가 기동하지 못할 때입니다. 운영 알림은 기본으로 켜져 있으며 GAEA_OPS_ALERTS=0 으로 끕니다. 메일은 어드민 콘솔의 메일(SMTP) 설정이나 SMTP_* 환경변수를 씁니다. SMTP 가 없으면 로그로만 남기며, 폐쇄망에서는 정상 동작입니다.
