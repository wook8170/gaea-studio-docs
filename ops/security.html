4. TLS 인증서 ​

인증서 일은 ./gaea.sh tls 하나로 합니다 — 점검·발급 요청서·설치·자체서명·검사. 인증서 디렉터리와 접속 주소는 .env 의 GAEA_TLS_CERT_DIR(기본 ./certs)·APP_BASE_URL 에서 읽습니다.

4-1 gaea.sh tls 명령 ​

표 4-1 하고 싶은 일과 명령

하고 싶은 일명령
지금 인증서가 괜찮은지(키 짝·만료·이름·체인)./gaea.sh tls status
사내 CA 에 낼 발급 요청서(CSR)./gaea.sh tls csr [--san 이름1,이름2]
받은 인증서 설치./gaea.sh tls install <인증서> <개인키> [<체인>]
임시 자체서명(825일) 만들기·갱신./gaea.sh tls selfsigned [--renew]
배치하지 않고 파일만 검사./gaea.sh tls check <인증서> <개인키>

공통 옵션: --dir <인증서 디렉터리> · --host <접속 호스트>(.env 가 아직 없을 때) · --no-apply(edge 반영 생략). 결과는 사전 점검과 같은 [ok]/[경고]/[실패] + → 조치: 이고 「요약: 실패 N · 경고 N」으로 끝납니다. 실패가 있으면 종료코드 1.

4-2 사내 CA 발급본 받기 ​

절차

  1. 발급 요청서를 만듭니다. 이름은 APP_BASE_URL 의 호스트이고 SAN 에 자동으로 들어갑니다. 다른 이름·IP 로도 접속하면 --san 으로 추가합니다(IP 는 자동으로 IP: 항목).

    sh
    ./gaea.sh tls csr
#   요청서: certs/request-<시각>/server.csr   ← 사내 CA 에 제출
#   개인키: certs/request-<시각>/server.key   ← 서버 밖으로 보내지 않습니다(권한 600)

  2. 발급본(인증서 + CA 가 준 중간 인증서)을 받으면 설치합니다. 체인을 따로 받았으면 세 번째 인자로 줍니다.

    sh
    ./gaea.sh tls install <발급받은 인증서.crt> certs/request-<시각>/server.key [<체인.crt>]
#   배치: certs/server.crt · server.key (이전 것은 certs/backup-<시각>)
#   확인: 포트 443 가 새 인증서를 내보냅니다.

install 은 검사에서 [실패](짝이 아님·만료·읽을 수 없음·암호 걸린 키)가 하나라도 나오면 배치하지 않습니다. edge 의 nginx -t 가 실패하면 보관한 옛 인증서로 스스로 되돌립니다.

참고 웹 마법사 3단계 「사내 CA 에 발급 요청」은 같은 일을 화면으로 합니다 — ① [요청서 만들기] → [요청서 내려받기(server.csr)]·[요청서 복사] ② 발급본을 「② 발급받은 인증서 넣기」에 붙여넣거나 파일로 고른 뒤 [검사 후 설치]. 개인키는 붙여넣지 않습니다(① 에서 서버에 만든 것을 씁니다). 발급이 늦으면 「자체서명」으로 먼저 설치하고 나중에 ./gaea.sh tls install 로 바꿉니다. 설치 전(.env 없음)에 터미널로 요청서를 만들려면 ./gaea.sh tls csr --host <접속 호스트>.

4-3 갱신·교체 ​

절차

  1. 지금 상태를 봅니다 — ./gaea.sh tls status(「만료 30일 이내」 경고 · 「위험 — 만료 임박」(7일 이내) · 만료면 실패).
  2. ./gaea.sh tls csr 로 새 요청서를 만들어 사내 CA 에 냅니다(개인키도 새로 생깁니다).
  3. ./gaea.sh tls install <발급본> certs/request-<시각>/server.key [<체인>] — 마지막 줄 「확인: 포트 443 가 새 인증서를 내보냅니다.」가 성공입니다. edge 를 재기동하지 않고 reload 하므로 접속이 끊기지 않습니다.
  4. 다중 노드에서 노드 edge 가 TLS 를 푸는 구성이면 모든 노드에서 3번을 반복합니다(같은 발급본·같은 개인키 파일을 각 노드로 옮겨서).

경고 edge 는 Strict-Transport-Security: max-age=31536000 을 붙입니다. 한 번 접속한 브라우저는 1년 동안 이 주소를 HTTPS 로만 열고, 인증서 오류를 사용자가 무시하고 넘어갈 수 없습니다. 만료되면 화면이 막히므로 만료 전에 교체합니다. 모니터링에는 openssl x509 -in certs/server.crt -noout -checkend 2592000(30일 안에 만료면 종료코드 1)도 쓸 수 있습니다.

gaea.sh tls 가 없는 이전 번들은 openssl 로 직접 합니다. 만료일 확인 → 키 짝 확인(공개키 해시 비교) → 옛 파일 .bak-* 보관 → 교체 → ./gaea.sh restart → openssl s_client 로 새 만료일과 Verify return code: 0 (ok) 확인 순서입니다.

4-4 체인 · 개인키 요건 ​

표 4-2 인증서 요건 — tls status·check·install 이 자동으로 봅니다

항목요건
체인server.crt 하나에 서버 인증서 → 중간 인증서(들) 순서로 넣습니다(루트는 넣지 않아도 됩니다). edge 는 체인 파일을 따로 받지 않으므로, tls install 의 세 번째 인자로 주면 이어 붙여 줍니다
이름(SAN)사용자가 주소창에 치는 이름이 SAN 에 있어야 합니다(CN 만으로는 최신 브라우저가 거부). IP 로 접속하면 IP: 항목
키 종류RSA·ECDSA 모두 가능(TLS 1.2·1.3)
개인키 암호비밀번호가 없는 키여야 합니다. 풀기: openssl pkey -in encrypted.key -out certs/server.key
권한chmod 600 certs/server.key(tls 명령이 맞춰 둡니다)

4-5 사내 CA 루트 배포 · HA 의 TLS 종단 · 리다이렉트 ​

항목내용
사내 CA 루트사용자 PC 가 사내 루트 CA 를 신뢰해야 경고 없이 열립니다(고객 PC 관리 영역). Windows 다수는 GPO 「신뢰할 수 있는 루트 인증 기관」, 한 대는 certutil -addstore -f Root <루트>.crt, macOS 는 security add-trusted-cert, Firefox 는 security.enterprise_roots.enabled
HA — A. TLS 통과모든 노드의 certs/ 에 같은 인증서(합류 꾸러미가 옮겨 줍니다). 갱신은 노드마다
HA — B. LB 종단 + 재암호화LB 에 공개 인증서, 노드에는 LB 가 신뢰하는 인증서. LB 인증서 갱신은 LB 절차
HTTP → HTTPS 리다이렉트GAEA_HTTPS_PORT 가 443 이 아니면 리다이렉트 주소에 포트를 붙입니다(https://$host:<포트>…). 이전 버전 edge 이미지는 포트를 붙이지 않아 8443 설치에서 http:// 접속이 열리지 않습니다

7. 키 관리 (백업 암호화 · 키 로테이션) ​

Node 내장 crypto(AES-256-GCM)만 사용 — 신규 런타임 의존성 0.

7-1. 백업 암호화(opt-in) ​

  • GAEA_BACKUP_ENC_KEY(32바이트 base64 또는 64자 hex)를 설정하면 온라인 백업(OB4)·정지 백업 CLI (dist/scripts/backup.js) 양쪽 모두 산출물을 스트리밍 AES-256-GCM 으로 암호화합니다(파일명.enc). 미설정 이면 현행 평문 그대로(무중단·무회귀). 부터 설치 마법사(setup.sh)가 비어 있으면 생성합니다 (--no-backup-enc-key 로 끕니다). 업그레이드 스크립트는 만들지 않으므로 기존 설치본은 그대로 동작하고, 마법사를 다시 돌려 키가 생기면 그 뒤 백업부터 .enc 다(그 전의 평문 백업도 그대로 복원됩니다).
  • .enc 포맷: 헤더 magic(7B "GAEAENC") + version(1B) + keyFingerprint(8B) + iv(12B) → 스트리밍 ciphertext → 트레일러 authTag(16B). fingerprint 는 SHA-256(key) 앞 8바이트 — 키 원문은 어디에도 남기지 않고 어느 키로 암호화됐는지 식별하는 용도입니다.
  • manifest.json 에 encrypted:true + keyFingerprint 가 기록됩니다(키 설정 시에만 — 미설정 시 필드 자체가 없습니다).
  • 복호: apps/server 에서 npx tsx scripts/backup-decrypt.ts <파일.enc> [출력경로] — env 의 GAEA_BACKUP_ENC_KEY(+_PREVIOUS)에서 헤더 fingerprint 로 맞는 키를 자동 선택합니다. 복원 절차의 위치는 ** (d) 복원 절차**.

7-2. ⚠ 키 분실 = 복구 불가 (키 2종 모두 이중 보관 필수) ​

백업 매체에는 키가 들어 있지 않다(비밀을 백업에 싣지 않는 설계 — (e) 준비물 표). 따라서 아래 2종은 백업과 별개로 보관해야 하며, 분실 시 잃는 것이 서로 다릅니다:

키분실 시되살릴 방법
GAEA_BACKUP_ENC_KEY그 키로 암호화한 백업은 영구히 복원 불가(백업 파일 자체에 복구 경로 없음)없음
GAEA_DATASOURCE_CONFIG_KEY데이터·설정은 복원되지만 데이터소스 자격증명 + 2FA(TOTP) 등록분만 복호 불가데이터소스 비밀번호 전량 재입력 + 사용자 2FA 재등록(운영 중단은 아니나 전수 작업)

운영 필수 사항(두 키 공통):

  • 키를 최소 2곳(예: 운영 시크릿 매니저 + 오프사이트 봉인 보관)에 이중 보관합니다. 백업 산출물과 같은 볼륨/매체에 키를 함께 두지 않는다(매체 도난 시 암호화가 무의미해집니다).
  • 신규 호스트 DR 은 이 보관본이 있어야 완결된다 — 호스트가 통째로 사라지면 .env 도 함께 사라집니다. DR 준비물 점검은 (e).
  • 키 교체 전에는 반드시 구키가 여전히 유효한 상태에서 신키를 발급·검증합니다(백업키 회전, config 키 회전 — config 키는 _PREVIOUS 개념이 없어 회전 = 전량 재암호화이고, 회전 직후 구키 보관본도 회전 전 백업의 복원을 위해 계속 보관합니다).

보관본 만들기 — ./gaea.sh keys export. 번들 디렉터리에서 실행하면 위 2종 + 번들 PG 비밀번호 (GAEA_META_PG_PASSWORD) + SSO state 서명키(SSO_STATE_SECRET)의 값과 지문(SHA-256 앞 16자)을 담은 키 복구 시트를 0600 파일로 만듭니다(--out <파일>, --encrypt = 암호로 잠금). 화면에는 지문만 찍습니다. 설치 마법사는 키를 새로 만들었을 때 이것을 자동으로 만들고 경로를 알려 줍니다 — 그 파일을 서버 밖(USB·금고·사내 비밀 보관소)으로 옮기고 서버에서는 지웁니다(shred -u). 지문은 백업 .enc 헤더의 keyFingerprint(앞 8바이트 = 16 hex)·서버 [ha] 키 불일치 메시지와 같은 규칙이라 「어느 키가 맞는가」를 값 없이 대조할 수 있습니다.

다중 노드 — 키는 전 노드가 같아야 합니다. GAEA_DATASOURCE_CONFIG_KEY·SSO_STATE_SECRET·GAEA_BACKUP_ENC_KEY 는 노드마다 다르면 각각 공유 메타DB 의 접속정보 복호 실패·다른 노드로 돌아온 SSO 로그인 실패·리더가 바뀔 때마다 다른 키의 백업이 됩니다. 추가 노드는 1번 노드에서 ./setup.sh --export-join <파일> 로 만든 꾸러미를 ./setup.sh --join <파일> 로 받아 설치합니다(키를 새로 만들지 않습니다). 서버는 HA 모드 부팅 때 GAEA_DATASOURCE_CONFIG_KEY 의 지문(SHA-256 — 키 아님)을 메타DB app_settings 의 ha.config_key_fingerprint 행에 등록·대조하고, 다르면 [ha] GAEA_DATASOURCE_CONFIG_KEY 가 다른 노드와 다릅니입니다 … 로 기동을 중단합니다(양쪽 지문 앞 16자·먼저 등록한 노드를 메시지에 싣습니다). 전 노드의 키를 의도적으로 바꿨다면(현재 회전 CLI 는 SQLite 전용) 그 행을 지운 뒤 기동합니다.

7-3. 백업키 회전 — GAEA_BACKUP_ENC_KEY_PREVIOUS ​

  1. 신규 키를 생성합니다: node -e "console.log(require('crypto').randomBytes(32).toString('base64'))".
  2. GAEA_BACKUP_ENC_KEY 를 신키로 교체하고, GAEA_BACKUP_ENC_KEY_PREVIOUS 에 구키를 넣는다(서버 재시작). 이후 백업은 신키로 암호화되지만, 복호 시(복호 CLI)엔 두 키 모두 후보라 fingerprint 로 자동 선택 — 구세대(구키 암호화)·신세대(신키 암호화) 백업이 모두 복원 가능하게 유지됩니다.
  3. 보존 세대(보존 설정)가 전부 신키 산출물로 교체된 뒤에는 GAEA_BACKUP_ENC_KEY_PREVIOUS 를 제거해도 됩니다 — 단, 오프사이트에 보관 중인 구세대 백업(재해 대비 오프사이트 복제)이 남아 있다면 그 복원을 위해 구키를 별도 안전 보관은 계속 유지합니다(환경변수에서만 제거).
  4. 회전 주기 권고: 정기 회전(예: 연 1회 또는 인원 변동·유출 의심 시 즉시) — 회전 자체는 새 백업부터 적용되므로 즉시 반영되고, 과거 백업 재암호화는 필요 없습니다(구키 보관으로 복원 가능성 유지가 더 실용적).

7-4. config 암호화 키(GAEA_DATASOURCE_CONFIG_KEY) 회전 ​

이 키는 datasource 자격증명 + TOTP secret(2FA) 저장에 쓰입니다(백업키와 별개 — apps/server/src/ credentials.ts). 백업키와 달리 회전 시 전량 재암호화가 필요합니다(회전해도 구키 산출물이 남으면 그 값들은 구키로만 복호되기 때문 — PREVIOUS 개념이 없습니다).

  1. 서버 정지(오프라인 도구 — 정지 상태에서만 실행).
  2. 신규 키를 생성합니다(1번과 동일 명령).
  3. 회전 CLI 실행 — CLI 는 런타임 이미지 안에 있다(src/scripts/ 편입). 폐쇄망 정본 경로는 컨테이너 실행이며 저장소 체크아웃·pnpm install 이 필요 없습니다:
bash
  # 폐쇄망(번들만 있는 호스트) — 서버 정지 상태에서
  docker compose run --rm --no-deps --entrypoint node server \
    dist/scripts/rotate-config-key.js --db /data/gaea.db \
    --new-key <신키> [--old-key <구키, 미지정 시 GAEA_DATASOURCE_CONFIG_KEY env>] \
    [--backup-dir /data/backups] [--dry-run]

  # 저장소 체크아웃이 있는 개발 호스트 — apps/server 에서
  npx tsx src/scripts/rotate-config-key.ts --db <gaea.db 경로> \
    --new-key <신키> [--old-key <구키, 미지정 시 GAEA_DATASOURCE_CONFIG_KEY env>] \
    [--backup-dir <dir>] [--dry-run]
  • 사전 백업이 자동 강제됩니다(--dry-run 이 아니면 회전 전 정지 백업을 먼저 실행하고, 실패 시 회전을 중단합니다) — 회전이 잘못돼도 백업으로 되돌릴 수 있게 합니다.
  • --dry-run: 구키 복호 검증만 하고 DB 에 아무것도 쓰지 않는다(사전 리허설용).
  • 대상: data_sources.config(암호화된 것만 — 평문 행은 건너뜁니다, 부팅 시 현재 키로 자동 승격되므로 회전 대상이 아닙니다) + user_totp.secret_enc 전량. 단일 트랜잭션이라 중간에 실패하면 전체 롤백됩니다.
  1. 완료 후 GAEA_DATASOURCE_CONFIG_KEY env 를 신키로 교체하고 서버를 기동합니다 — 이 시점부터 신키만 유효(구키로는 더 이상 복호되지 않습니다).
  2. 검증: 커넥터 접속 테스트(데이터소스 상세 "연결 테스트") + 2FA 로그인 1회로 TOTP 가 정상 동작하는지 확인합니다.

7-5. 키 로그 금지 (감사 원칙) ​

두 키(GAEA_BACKUP_ENC_KEY*, GAEA_DATASOURCE_CONFIG_KEY) 원문은 어떤 로그·에러 메시지·manifest 에도 남기지 않는다 — 노출되는 것은 8바이트 fingerprint(hex)뿐입니다. 키가 노출되면 secrets 운영 원칙에 따라 즉시 회전 대상으로 봅니다.
