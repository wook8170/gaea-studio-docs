create_report_schedule ​

확인 필요(confirm) 변경

저장된 보기(view) 또는 대시보드를 주기적으로 렌더링해 이메일 발송 예약해요(daily/weekly/monthly). 대상은 savedViewId(보기) 또는 dashboardId(대시보드) 중 하나만 줘요(둘 다 주면 400). format 은 pdf·xlsx·pptx·hwpx 중 하나이며 대시보드 대상은 pdf 만 지원해요(그 외 422). hwpx(한글)는 Enterprise 에디션 전용이에요(Standard·무라이선스는 403 feature_gated — 다른 형식을 권해요). hour 는 UTC 로 저장되므로 호출측이 KST→UTC 로 변환해서 넘겨야 해요(예: KST 9시 → hour: 0). weekly 는 weekday(0=일~6=토) 가, monthly 는 dayOfMonth(1~28, 29일 이후는 없는 달이 있어 미지원) 가 필요해요. 수신자는 멤버 이메일이면 항상 허용되고, 외부(비멤버) 주소는 워크스페이스 수신자 정책(owner 가 허용 도메인을 지정해 켜요)에 맞아야 하며 위반은 422 로 거절돼요 — 외부 주소가 섞인 예약은 감사 로그에 남아요. skipEmpty=true 면 결과가 비었을 때 그 회차 발송을 건너뛰어요. notifyChannelIds 로 발송 결과를 외부 알림 채널에도 통지해요(없는 채널이면 422). 워크스페이스 반출 권한이 필요해요(서버 강제). confirm 없이 부르면 요약만 반환하고 예약을 만들지 않아요. 예: "매주 월요일 KST 9시에 매출 보기 PDF 를 a@b.com 에 보내줘" → create_report_schedule({ workspaceId, savedViewId, format: "pdf", cadence: "weekly", hour: 0, weekday: 1, recipients: ["a@b.com"] }) 후 confirm:true.

create_report_schedule({ workspaceId: string, targetKind?: "view" | "dashboard", savedViewId?: string, dashboardId?: string, format: "pdf" | "xlsx" | "pptx" | "hwpx", cadence: "daily" | "weekly" | "monthly", hour: integer, weekday?: integer | null, dayOfMonth?: integer | null, recipients: string[], skipEmpty?: boolean, notifyChannelIds?: string[], confirm?: boolean })
인자형식필수설명
workspaceIdstring예대상 워크스페이스 id.
targetKind"view" | "dashboard"대상 종류. 미지정이면 savedViewId 가 있으면 'view', dashboardId 만 있으면 'dashboard'(하위호환).
savedViewIdstringtargetKind='view' 의 대상 보기 id. 엔드포인트가 연결돼 있어야 하고(422), 남의 비공개 보기는 403.
dashboardIdstringtargetKind='dashboard' 의 대상 = 대시보드(프로젝트) id. 대시보드 대상은 pdf 만 지원해요.
format"pdf" | "xlsx" | "pptx" | "hwpx"예첨부 형식(대시보드 대상은 pdf 만 · hwpx 는 Enterprise 전용).
cadence"daily" | "weekly" | "monthly"예발송 주기.
hourinteger예발송 시각(UTC, 0~23).
weekdayinteger | nullcadence=weekly 일 때 필수(0=일~6=토).
dayOfMonthinteger | nullcadence=monthly 일 때 필수(1~28).

skipEmptybooleantrue=결과가 비면 그 회차 발송을 건너뛰어요(기본 false: 빈 표도 발송).
notifyChannelIdsstring[]발송 결과를 통지할 외부 알림 채널 id 목록(최대 50). 없는 채널이면 422.

subscribedboolean예true=내 주소를 수신자에 추가, false=내 구독 해지.

get_my_subscriptions({ limit?: integer })

create_data_alert ​

확인 필요(confirm) 변경

데이터 알림을 만들어요 — 저장된 보기(view)의 수치 측정값(field)이 조건을 만족하면 주기적으로 이메일 발송. op: gt(초과)·lt(미만)·between(threshold~threshold2 구간)·change_pct(직전 대비 변화율%)·stddev(과거 평가값 평균에서 threshold×표준편차 이탈)·iqr(과거 평가값 사분위 범위 밖, threshold=배수 1.5 권장). stddev·iqr 는 과거 평가값이 최소 8주기 쌓인 뒤부터 발화해요(그전에는 조용히 기준선만 수집). hour 는 UTC 로 저장하므로 호출측이 KST→UTC 로 변환해 넘겨요(예: KST 9시 → hour: 0). weekly 는 weekday(0=일~6=토), monthly 는 dayOfMonth(1~31, 없는 날은 말일로 클램프) 필요. between 은 threshold2(상한)가 필요하고 하한 ≤ 상한. field 후보/현재값은 GET /data-alerts/preview 로 확인(모달과 동일). 수신자는 기본 워크스페이스 활성 멤버만(서버 강제). reNotify=true 면 조건이 계속 참일 때 매 주기 재알림(기본은 상태 변화 시에만). confirm 없이 부르면 요약만 반환. 예: "매출 보기가 1억 넘으면 매일 KST 9시에 a@b.com 에 알려줘" → create_data_alert({ workspaceId, savedViewId, field: "매출", op: "gt", threshold: 100000000, cadence: "daily", hour: 0, recipients: ["a@b.com"] }) 후 confirm:true.
