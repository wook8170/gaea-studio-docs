get_view_history ​

조회

저장된 보기(view)의 버전 이력(세대별 이름·변경 주체·시각)과 인증(Endorsed) 배지 상태를 돌려줘요. restore_view 로 되돌릴 version 을 고르기 전에 먼저 불러요. private 보기 이력은 생성자만 볼 수 있어요(서버 강제). endorsement 가 null 이 아니면 현재 내용이 인증된 내용이라는 뜻이에요(인증은 버전에 고정되며 내용이 바뀌면 자동 해제돼요). 예: "이 보기 버전 이력 보여줘" → get_view_history({ viewId }).

ts
get_view_history({ viewId: string })
인자형식필수설명
viewIdstring예이력을 볼 보기 id.

restore_view ​

확인 필요(confirm) 변경

보기를 특정 과거 버전(version)으로 되돌려요 — 복원 자체가 새 세대를 남겨 다시 롤백할 수 있어요(파괴적 아님). 생성자 또는 owner 만 가능(서버 강제). version 은 get_view_history 의 세대 번호. confirm 없이 부르면 대상· version 요약만 반환하고 실행하지 않아요(현재 구성을 통째로 덮으므로). 예: "이 보기를 3번 버전으로 되돌려줘" → restore_view({ viewId, version: 3 }) 후 confirm:true.

ts
restore_view({ viewId: string, version: integer, confirm?: boolean })
인자형식필수설명
viewIdstring예복원할 보기 id.
versioninteger예되돌릴 세대 번호(get_view_history 의 version).
confirmboolean

endorse_view({ viewId: string })

데이터셋(엔드포인트)에 인증(Endorsed·검증됨) 배지를 부여해요 — owner 전용(서버 강제). 조직이 신뢰하는 공식 데이터셋임을 표시해요(unendorse_endpoint 로 수동 해제). 인증은 인증한 시점의 데이터셋 구조 (컬럼 이름·타입, 소스 쿼리, 적재 방식, 원본 테이블명)에 고정되어, 이후 구조가 바뀌면 서버가 배지를 자동으로 내려요 — 그러므로 컬럼/쿼리 수정을 모두 끝낸 뒤 마지막에 불러요. 새로 적재해 행이 바뀌는 것은 해제 사유가 아니다(구조가 그대로면 배지도 그대로). 예: "이 데이터셋 인증 배지 달아줘" → endorse_endpoint({ endpointId }).

get_endpoint_config_history ​

조회

데이터셋(엔드포인트)의 설정을 바꾼 시점 목록을 돌려줘요 — 적재 방식·동기화 주기·증분 키·실시간 설정과 필드 설정(표시명·역할·숫자 형식·셀 표시 방식·날짜로 취급·컬럼 순서)이 대상이에요. restore_endpoint_config 로 되돌릴 version 을 고르기 전에 먼저 불러요. 각 행의 origin 은 baseline(처음 설정)·edit(설정 변경)· restore(되돌림, restoredFrom 에 되돌린 번호)다. settings.enabled 가 false 면 이 워크스페이스에서 기능이 꺼져 있어 새 시점이 쌓이지 않아요(복원도 거절돼요). canRestore 가 false 면 요청자에게 복원 권한이 없어요. 적재 진행 상태·인증 배지·카탈로그·행 정책은 이 이력에 없다. 예: "이 데이터셋 설정 언제 바꿨는지 보여줘" → get_endpoint_config_history({ endpointId }).

ts
get_endpoint_config_history({ endpointId: string })
인자형식필수설명
endpointIdstring예설정 이력을 볼 데이터셋(엔드포인트) id.

get_endpoint_config_version ​

조회

데이터셋 설정 이력의 한 시점을 미리 봐요 — 그 시점의 설정 전체(snapshot)와 두 방향 비교를 줘요: diffFromPrev 는 「그때 무엇을 바꿨나」(직전 시점 대비), diffFromCurrent 는 「되돌리면 이렇게 바뀝니다」 (지금 설정 대비)다. 되돌리기 전에 반드시 이것으로 확인시켜라 — diffFromCurrent 가 빈 배열이면 지금 설정과 같아서 되돌릴 것이 없어요. version 은 get_endpoint_config_history 의 세대 번호. 예: "3번 시점으로 되돌리면 뭐가 바뀌어?" → get_endpoint_config_version({ endpointId, version: 3 }).

ts
get_endpoint_config_version({ endpointId: string, version: integer })
인자형식필수설명
endpointIdstring예데이터셋(엔드포인트) id.
versioninteger예미리 볼 시점 번호(get_endpoint_config_history 의 version).

restore_endpoint_config ​

확인 필요(confirm) 변경

데이터셋(엔드포인트)의 설정을 특정 시점으로 되돌려요 — 복원 자체가 새 시점을 남겨 다시 앞으로 갈 수 있어요(파괴적 아님). editor 이상만 가능(서버 강제). confirm 없이 부르면 대상·version 요약만 반환하고 실행하지 않아요(지금 설정을 통째로 덮으므로). 되돌리지 못하는 것 둘: 커스텀 쿼리(SQL)는 컬럼 세트 재생성을 동반해 이력이 적용하지 않고 경고만 내요 · 그 시점 이후 사라진 컬럼의 설정은 건너뛰어요 — 둘 다 응답 warnings 에 와요. 워크스페이스에서 설정 이력이 꺼져 있으면 422 로 거절돼요. 증분 키가 바뀌는 복원은 적재 워터마크를 함께 리셋하므로 다음 동기화가 전량 재적재가 돼요(데이터 정합성 보호). 예: "이 데이터셋 설정을 2번 시점으로 되돌려줘" → restore_endpoint_config({ endpointId, version: 2 }) 후 confirm:true.

versioninteger예되돌릴 시점 번호(get_endpoint_config_history 의 version).
