POST /api/bi-connect/redeem ​

공개 인증 시험 모드에서 차단

연동 초대 교환 — 본문 code

자세히

연동 초대 교환 — 본문 code(폼 -d code=… 또는 JSON). IP rate limit 기본 10회/분(429 + Retry-After) · 모름/취소 401 invite_invalid · 재사용 401 invite_used · 만료 401 invite_expired · 작성자가 지금 owner 아님 403 invite_creator_not_owner · 등급/캐파/주소 실패는 키 발급과 같은 코드(초대는 소모되지 않음). 성공 201 · no-store: Accept: application/json 이면 { host, siteId, kid, signingSecret, tokenPath, keyExpiresAt, env }, 아니면 text/plain .env 본문(GAEA_BI_HOST·GAEA_BI_SITE_ID·GAEA_EMBED_KID·GAEA_EMBED_SIGNING_SECRET). 키는 초대 작성자 명의 · 키 발급 라우트와 같은 issueSiteKey. 감사 BI_SITE_CONNECT_REDEEM(코드·비밀 미기록)

요청 본문 application/json · 모델 PostBiConnectRedeemRequest

codeany

응답

  • 200성공했어요
  • 400보낸 값이 맞지 않아요 — invalid_body
  • 403권한이 없어요(역할 · 토큰 범위 · 읽기 전용 토큰 · 임베딩 주소) — invite_creator_not_owner
  • 429너무 자주 불렀어요 — Retry-After 초 뒤에 다시 불러요 — rate limit exceeded

성공 응답 필드: env 외 더 있음

오류 본문은 { "error": "코드", "message": "설명" } 형태예요.

curl -X POST 'https://gaea.example.com/api/bi-connect/redeem' \
  -H "Authorization: Bearer $GAEA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'

POST /api/bi-connect/rotate ​

공개 인증 시험 모드에서 차단

연동 키트가 자기 서명 비밀을 스스로 교체해요

자세히

호스트 자동 연동 (키트 자동 회전 pull) — 본문 { kid, ts(초), nonce(base64url 16..43), sig = base64url(HMAC-SHA256(현재 서명 비밀, kid + '.' + ts + '.' + nonce)) }. 순서: 모양 400 invalid_body → IP 10회/시간(429) → 키 없음/embed 아님/내부 키/autoRotatePull 꺼짐 404 → \|ts−now\|>60초 401 → 서명 불일치(현재 비밀만, prev 불가) 401 → nonce 1회용(consumeJtiOnce) 401 → 키당 1회/24시간(429) → 회전(prev=지금 비밀 · graceUntil=+7일 · 새 비밀). 성공 200 { signingSecret, graceUntil, kid } · no-store. 감사 EMBED_KEY_ROTATE_PULL + owner 인앱 알림 + 메일. 키를 찾은 뒤의 401 3종(시각·서명·재사용)은 owner 에게 거부 알림(인앱 + 메일 · 키당 하루 1회 — rate limit 버킷 reject-alert:<kid> · 응답은 그대로 401). 서버 쪽 키별 opt-in 플래그(PATCH /auth/keys/:id · 기본 off) 없이는 항상 404 — 유출된 비밀로 새 비밀을 당겨갈 수 있는 경로라 조건

요청 본문 application/json · 모델 PostBiConnectRotateRequest

tsany
nonceany
sigany

  • 200성공했어요

  • 404대상을 찾지 못했어요 — not found
  • 429너무 자주 불렀어요 — Retry-After 초 뒤에 다시 불러요 — rate limit exceeded

GET /api/site-runtime/:siteId ​

로그인 세션 · 개인 액세스 토큰 · 임베딩 키 인증 시험 모드에서 차단

BiRuntime — 사이트 · 리비전 · 메뉴 · 대시보드(이름·페이지) · 변수 정의 · 적용 값 · 조회자

자세히

BiRuntime — 사이트 · 리비전 · 메뉴 · 대시보드(이름·페이지) · 변수 정의 · 적용 값(applied) · 조회자. v2: 응답에 pages: BiRuntimePage[](정규화된 사이트 페이지 — type·source·치환된 title({{변수}} 를 서버가 적용 값으로 렌더) · titleTemplate?(제목에 {{변수}} 가 있을 때만 원문 템플릿. 화면이 호스트 값으로 같은 renderPageTitle 로 재치환해요)·visible(visibleWhen 평가 결과) · 분석형이면 analysis.viewer(얼린 「열어 줄 기능」 — 비세션은 savePrefs 닫힘)·analysis.initial)와 theme: BiSiteTheme(배치·GNB 높이·LNB 폭·색·로고 — v1 게시본은 appearance 에서 파생하므로 항상 있다)가 실리고, 메뉴 노드에 visible 이 붙어요. v2(-Task 12): pages[]·menu[].visible 이 자리표시자(빈 배열·항상 true)에서 실값으로 전환 — pages 는 openDashboards/frozenAnalysis(살아 있는 대시보드·분석형만) 필터 후 실제 목록, visible 은 evaluateCondition(visibleWhen, values) 실평가. v1 게시본에도 합성 linked 페이지가 내려가므로 클라이언트는 v2 한 모양만 봐요. (오너 결정): 응답에 allowedOrigins: string[](사이트 「고객 포털 주소」 — origin 만 · 소문자 · 중복 제거, bi-core normalizeSiteOrigins)가 실려요 — 화면이 iframe 안이면 부모 origin(location.ancestorOrigins → document.referrer → ?sdkOrigin=)을 이 목록과 대조해 밖이면 콘텐츠 대신 「이 주소에서는 열 수 없어요」 안내를 그리고 데이터를 요청하지 않아요(siteFrameAllowed · 빈 목록 = 제한 없음 · 부모가 Gaea 자신이면 통과). 목록 밖 Origin/Referer 로 부르면 403 site_origin_denied(서버 보조 층). (오너 결정): 응답에 colorMode: 'light' \| 'dark' \| 'auto'(사이트 「화면 테마」 — 게시본에 얼린 값 · ?preview=draft 면 초안 값 · 키가 없는 옛 게시본은 auto, bi-core normalizeSiteColorMode)가 실려요. 조회 문서는 고정(light·dark)이면 보는 사람 OS 설정 대신 이 값으로 그리고, 호스트가 명시한 ?theme=·SDK setTheme 은 여전히 이겨요(우선순위 = 호스트 명시 > 고정값 > auto 일 때만 OS). 초안 문서 BiSiteDoc.colorMode?(포털 · 끼워 넣기 공통 · schema 1·2 모두, 부재 = auto · 그 밖 값은 400 invalid_draft)를 바꿔도 다시 게시해야 반영돼요 — 「바뀐 것」 에 target: 'colorMode' 한 줄(부재 ↔ auto 는 같은 값). visible: false 는 표시 전용이라 접근 제어가 아니다 — 숨긴 페이지도 id 를 알면 열려요(막는 것은 audience 와 잠근 변수예요). ?preview=draft = editor 세션만 초안. ?dashboard=(+?page=)로 첫 화면 지정(허용 목록 밖이면 오류 대신 시작 화면 + warning). 미게시 404 site_not_published · audience 불일치 403 site_audience_denied · 잠긴 값 누락(비세션은 required 무관 항상 필수)/형식 불일치 403 site_param_missing/site_param_invalid(+paramLabels, 서명 없는 자격이면 reason) · 그 밖 인가 실패는 404. (오너 지시 혼란 전수 검사 A4 · A5): pages[] 에 boundParams?: string[](이 페이지 조회에 필드로 이어진 변수 이름 — 대시보드형은 그 페이지 위젯, 분석형은 그 보기의 엔드포인트에서 resolveParamBinding 결과 필드가 엔드포인트 필드에 있는 변수 · 단위별 묶음 치환 반영. 화면 값 고르기 줄이 이 변수만 그리고 빈 배열이면 줄을 숨겨요 · 부재 = 옛 응답, 전부 표시)가 실리고, 「자동으로 채우기」 규칙 메뉴 노드는 값이 더 있으면(출처 창 잘림 · 상한 초과) truncated: true 를 실어요 — 화면 · SDK getMenu 가 끝에 「더 보기」(more: true · id <규칙 id>::more)를 붙여요(응답 자체에는 more 노드가 없어요)

팝업이 여는 첫 화면 — 쿼리는 무시하되 예외 하나: 선택 ch…

자세히

팝업이 여는 첫 화면 — 쿼리는 무시하되 예외 하나: 선택 ch(대체 채널 id · /^[A-Za-z0-9_-]{22,64}$/ · 틀리면 버림 · 서명 tx 쿠키에만 싣고 IdP 로는 보내지 않음). IdP authorization_endpoint 로 302(PKCE S256 + state HMAC + tx 쿠키 gaea_site_sso_tx, Path=/api/site-sso/<id>/, Max-Age 600, HttpOnly, SameSite=Lax). SSO 미설정·게이트 미보유는 404 통일(존재 여부를 흘리지 않아요). 셸 오리진: 요청 Referer 의 오리진만 읽어 Gaea 오리진 허용 목록(앱 주소 오리진 + 이 사이트 SSO 내부 키 allowed_origins · 정확 scheme+host+port 일치)에 있을 때만 서명 tx 쿠키 o 에 실어요(state · IdP 로는 안 보냄 · 목록 밖 · 없음 = 버림). 호스트 튕김: 그 셸 오리진과 요청 호스트(req.hostname)의 호스트 이름이 둘 다 앱 주소(resolveAppBaseUrl · 기본값이 아닐 때만)와 다르면 tx 쿠키 · IdP 302 대신 302 <앱 주소>/api/site-sso/:siteId/start?ch=<검증된 ch>&ret=<셸 오리진>(no-store · no-referrer · 비밀 0) — tx 쿠키가 콜백 호스트에 심기게 해요. ret 가 있는 두 번째 start 는 다시 튕기지 않고, ret 를 정규형 · 허용 목록 · (있으면) Referer 오리진과 다시 대조해 맞을 때만 o 로 써요(아니면 버림 = 상대 done). rate limit 은 두 start 모두 세요
